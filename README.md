# 数回 Slitherlink · 一条闭环，格子里的数字说它四边里有几条

在 `W×H` 的盘上画**一条**连续的环：环只能走格线，每个格点恰好接两段。格子里的数字 `0/1/2/3` 说
"我这个格子的四条边里，有几条在环上"（数字 `-1` 是空格，不给线索）。本仓出货的每一盘都只有一个
答案，而且每一盘都能用六条局部推理从空盘一路推到底——一次都不许靠猜。

本文里的数字只有两类来源：仓里读得到的代码（写成 `文件:行号`），和 **2026-09-28 这一轮全绿跑**
出来的读数。跑的命令是 `npm run check`、`npm test`（四套 62 / 40 / 89 / 406 条 + 一套穷举对账）、
`node tools/census.mjs`、`SAMPLES=24 node tools/balance.mjs`、`bash tools/verify.sh`，环境是
Node v26.8.1 / macOS 25.6.0 / Apple M5 Pro 15 核。断言条数与 `npm run check` 是当场重跑的；
难度与墙钟读数取自 07:4x 那一跑 balance（`RESULT ok=true`，总墙钟 19.7s，72 张抽卡），浏览器门禁
取自 08:0x 那一跑（31 条断言 0 失败 + 变异腿先红后绿）。

**这台机器当时 load average 30.30 / 33.86 / 29.56**（同目录树里别的会话在跑它们的测试），所以本文
所有**绝对毫秒都当悲观上界读**；分位数之间的相对关系、以及"哪一档的尾巴更肥"这类结论不受影响。

**代码 > 本文档**：本文与 `js/`、`tools/` 冲突时，以代码和它跑出来的输出为准。

## 规则（玩家视角）

1. **一条环**：环是连成一圈的单条闭合曲线，不分叉、不自交成两条。
2. **每个格点度数是 0 或 2**：环经过一个点就恰好进一次出一次，经过不了就一条都不接。
3. **数字 = 该格四边里在环上的条数**，`0` 表示四边全在环外，`3` 表示四边里恰好断一条。
4. 数字只是线索，**不是**对格的划分——盘上没有墙。

判胜不在界面里另起口径：赢 = 边全定完 ∧ 度数合法 ∧ 提示数字全对 ∧ 是单条环，六个判据按
`js/engine/verify.js:41` 的 `CHECK_ORDER = ['empty','clues','degrees','dot4','open','single']`
依次裁决（`verify()` 在 `:199`），赢只由它说了算。

- 玩家点的是**边**，不是格子。盘上的边一共 `E = w(h+1) + h(w+1) = 2wh + w + h` 条（`js/engine/grid.js:13-15`
  的 `nH` / `nV` / `E`；**含最外圈**，不只是内部边），每条三态：未定 / 在环上 / 打叉（确定不在环上）。
  打叉是人能直接说出口的结论（"`0` 的四边都得断"），所以这条通道一直留着。
- 坐标与边号的约定只有一份，写在 `js/engine/grid.js:1-12`（含 `cellEdges` 的 `[上,下,左,右]` 次序）。
  同一份定义被页面、生成器、计数器、判胜器和四套测试台共用——"什么算合法盘"写第二遍，两个台架就会
  各自把 bug 写成期望。

## 怎么玩

- **三档，全部是量出来的**：初学 4×4、熟练 5×5、高段 6×6（`js/engine/generate.js:75` 的 `TIERS`，
  表外尺寸由 `makePuzzle` 直接抛错——`sizeAllowed` 在 `:84`，天花板 `CEILING` 在 `:82`）。
  **6×6 之上本轮出不起货**，砍在 6×6 的两批独立读数与硬超时事故写在 `js/engine/generate.js:25-58`。
- 落子：**左键**点一条边的中点画上一段环，再点一下擦掉；**右键**打一个叉，再点一下取消
  （`index.html:63` 那句就是页面上的原文）。键盘通道 2 颗键：`F` 切全屏、`R` 重开本题
  （`js/main.js` 末尾那颗 `keydown` 监听）。两处护栏写死在监听里：焦点在 `input`/`textarea`/`select`
  里时一律不触发（输 seed 输到一半屏幕不能没），`repeat`/`meta`/`ctrl`/`alt` 也一律忽略；
  开局进行中（`busy`）按 `R` 无效。引擎侧 `js/ui/game.js` 里没有任何键盘监听——键只进界面。
  文档写的键集合与代码比对的键集合由 D8i 钉成一条对应等式，谁单方面多一颗少一颗都红；
  浏览器台架目前只走指针与按钮点击，这两颗键的**界面反应**不在那套场景里。
- 侧栏六个读数（环上的边 / 打了叉 / 还没定 / 环长 / 步数 / 引擎说）全部由引擎现算，不是界面自己数
  格子，六个 `.stat` 在 `index.html:76-81`；文档点名的 `#stat-on` / `#stat-off` 就是前两颗。页面一共 8 颗按钮
  （`id="btn-*"`，按 DOM 顺序：全屏 / 再来一局 / 就看不动 / 撤销 / 全清 / 重开本题 / 新的一局 / 清空存档），
  侧栏那三颗（撤销 / 全清 / 重开本题）在 `index.html:69-71`。
- 同一个 seed 永远画同一张盘：seed 串形如 `4x4#1-21aa83dbc239`（`js/main.js:55-60` 用
  `crypto.getRandomValues` 的 6 字节加一个自增计数，**不是**按日期算的——"新的一局"那颗按钮不许在
  你说"换一局"的时候其实端回今天那盘）。随机只发生在"选 seed"这一步，生成器内部零随机。
- 「新的一局」最多抽 `MAX_DRAWS = 24` 次（`js/main.js:32`），每次抽完让出一帧再抽
  （`drawPuzzle` 在 `:66-76`）；24 次都没出货就照直说"这一档今天开不了局"，不硬端一张没证完的盘。
- 存档一个键 `slither.save.v1`（`js/store.js:10`），里面只有 seed + 三态串 + 步数，**没有答案字段**
  （门禁的 `resume-set` 场景就是照着这条断言的，见下）。

## 这四条承诺，每一条怎么变成一条会红的命令

| 承诺 | 怎么检查 |
|---|---|
| **唯一解由独立 DP 数过**，不是"没找到第二个" | 出货前跑一次传递矩阵 DP：`countSolutions({w,h,clues}, {budget})`（`js/engine/counter.js:95`，预算 2,000,000 个状态），`makePuzzle` 把 `count / statesUsed / overbudget` 一起交出去（`js/engine/generate.js:236-254`）。`balance` 的 [G2] 拿**本轮出货的每一张盘**再核对一次：最终核对不是 `count===1`、或撞了预算、或铅笔没推到底 ⇒ 判红。本轮读数：**shipped-but-unproven 0 张**（72 抽），峰值状态用到预算的 0.01% / 0.13% / 0.48%（三档） |
| **零猜测**：出货的每一盘能用那六条从空盘推到底 | 铅笔求解器只用 `RULE_ORDER` 那六条、固定顺序、无回溯（`js/engine/pencil.js:397`、`:420`）。但这条要老实说：它是**流水线的定义**而不是独立闸——`dig` 只保留"铅笔推得完"的删除（`generate.js` 里 `rejectedPencil++` 那一支，现 `:163-166`），所以出货盘按构造必零回溯，有信息量的是差值 0 张。真正独立的那一头是穷举对账：`npm test` 的 counter-test 62 条里，DP 与朴素枚举在随机盘上**逐盘比解数**（含 0 解与多解） |
| **尺寸天花板是量出来的**：6×6 之上浏览器承诺不起"点一下等多久" | `js/engine/generate.js:25-58` 记着两批独立 seed 的 p95（7×7 = 4155 / 4450ms，红线 2.2 倍；其中一张 40s 硬超时还没出货）与 8×8 的真实分布（p95 92s）。`npm run ceiling` 重跑这张表，`npm run balance` 每轮把本档实测 p95 和 `TIERS` 里的常量并排打印（本轮 6×6 实测 p95 2085ms，见下） |
| **页面拿不到答案**，赢只由 `verify` 裁决 | 判胜只走 `js/engine/verify.js`；生成器交出的 `loop.edgeSet` 不进存档、不进 DOM。测试用的冻结答案边集放在 `tools/golden.mjs`，而 `pages.yml` **从不部署 `tools/`**，所以线上进不到它；门禁跑的时候由驱动器把这份磁盘字节当 Blob 模块注进页面（`tools/playtest.cjs` 的 `GOLDEN_LOADER`），三个 URL 形态吃的是同一批字节。会红的证人：`play` 场景点齐冻结环之后必须真赢、横幅真的长出来、环长等于 `verify` 给的 `len`；`fixture-mutation` 腿把冻结边号换一条，`play` 必须当场红 |

## 这个仓**不承诺**什么

- **不承诺「唯一解 ⟹ 这六条推得完」**。六条不完备，反方向不成立。今天 `node tools/census.mjs` 的
  第一列就是这件事的价码：**全提示盘**（一个数字都没挖）铅笔可完率 4×4 只有 **75.0%**（24/32）、
  5×5 **92.3%**（24/26）、6×6 **100.0%**（24/24，样本只有 24 张，别读成常数）。推不完的全提示盘，
  它的任何子集盘也推不完（`js/engine/generate.js:11-14` 那条信息单调的结构性事实），所以这是
  **出货率的上界**，不是可以靠重试抹掉的运气——`balance` 每轮都核对"实测上界 ≥ 已证出货率"（本轮
  83.3% / 100% / 100%，成立）。
- **不承诺"高段的每一盘都比熟练难"**。档位只在整体上可分（见下表 AUC 0.796 / 0.835，红线 0.75），
  档内离散 sd 4.6 / 12.5 / 18.7 与档间中位差是同一个量级：4×4 的最难一张（score 49）就比 5×5 的
  最易一张（score 24）高。归一化到"每格多烧脑"之后单调性直接散掉（每边分数 p50 0.98 → 0.85，
  每数字分数 5.67 → 5.17 → 5.17）。
- **不承诺等待时间**。墙钟是 DP 的成本，不是盘子的难度：score 与 engine ms 的 Spearman ρ 在 5×5 是
  **−0.29**、6×6 是 **−0.72**（4×4 的 0.13 不算读数——本档 engine ms 全落在 13~32ms，跨度 19ms，
  负载噪声就够把秩重排一遍）。6×6 里最慢的三张 3662 / 2085 / 1829ms，score 分别只有 **27 / 49 / 45**
  ——最慢的一张恰好是这一档最简单的一张。**慢的不能当难的销售点**。
- **`budgetMs` 不是对玩家的超时承诺**，页面上也没有那个兜底。`TIERS` 里的 `budgetMs / p95Ms / maxMs /
  cluesMedian / shipRate` 是当年 ceiling 那批 seed 的读数，`npm run balance` 会逐条打 ↔ 对照：本轮
  normal 的 `cluesMedian` 12 ↔ 实测 9、`p95Ms` 113 ↔ 278，hard 的 `p95Ms` 374 ↔ 2085、`maxMs`
  6330 ↔ 3662，easy 全部对得上。而 `budgetMs` **没有任何读取方**（全仓 grep 只有 `TIERS` 自己和
  `generate.js:49` 那段说明），也没有东西可以兜底：`makePuzzle` 是同步的、中途打不断，页面能做的只有
  让出一帧再抽下一张。真要兜底得先把出题搬进 worker——那是功能改动，不是改注释改出来的。
- **六条规则里有一条在出货盘上从未开过张**。`loop_closed`（权重 3，"环已闭合，环外全断"）本轮
  **0 / 68 张出货盘命中**（三档分别 0/20、0/24、0/24），五份冻结夹具的 `final.hits.loop_closed`
  也全是 0。所以"六条规则"这句话的实际内容是：**页面上生效的是五条**，第六条留着是因为它逻辑上
  成立、且随时可能被下一批 seed 用上——但它现在不构成任何难度证据。
- **不承诺题面极简**。挖数字是一边挖一边证"再挖就推不完 / 就不唯一"，但撞了预算的那一步会把数字放
  回去，于是那一颗数字是"预算逼着留的"，不是"证过必要的"。本轮 72 抽里 DP 撞预算 0 次
  （`overbudget=0`），所以这一档没吃到这条破口；读 `balance` 输出里的 `rejectedBudget` 列确认。

## 难度是量出来的

`SAMPLES=24 node tools/balance.mjs`（2026-09-28，72 张抽卡，`RESULT ok=true`）。分数是 balance
自定义的度量：`score = Σ 规则命中次数 × 权重`，权重按"这条规则要看多远"给（本格 1 / 共边 2 / 整圈
3 / 提前闭环 4，见 `js/engine/pencil.js:213-335` 的 `weight`），**不是引擎给玩家打的分数**。

| 档 | 尺寸 | 抽卡 → 出货 → 已证 | 数字数 p50(p95) | score p50 / p95 / max（min） | 要靠重规则才推得完 | engine ms p50 / p95 / max | 每张出货代价 |
|---|---|---|---|---|---|---|---|
| 初学 | 4×4 | 24 → 20 → **20** | 7 (10) | 39 / 49 / 49（32） | 7/20（35.0%） | 18.3 / 30.6 / 31.5 | 21.3ms |
| 熟练 | 5×5 | 24 → 24 → **24** | 9 (14) | 51 / 66 / 69（24） | 12/24（50.0%） | 51.9 / 278.3 / 315.3 | 70.9ms |
| 高段 | 6×6 | 24 → 24 → **24** | 15 (19) | 81 / 91 / 94（27） | 13/24（54.2%） | 100.8 / 2084.8 / 3661.9 | 465.7ms |

四道闸本轮的读数：

- **[G1] 样本量**：每档"已证"≥ 12。来历是 H0「标签与分数无关」下 AUC 的标准差
  `sqrt((n1+n2+1)/(12·n1·n2))`——n=12/12 时 sd = 0.120，红线 0.75 距 0.5 只有 2.08σ，判不出；
  n=24/24 时 sd = 0.084（2.97σ）。实测 20 / 24 / 24 ⇒ PASS。
- **[G2] 承诺完整**：unproven 0、超时 0、崩 0、铅笔复算不一致 0、同 seed 重复跑指纹不一致 0 ⇒ PASS。
- **[G3] 尺寸单调**：16 < 25 < 36 格 ⇒ PASS，但这条**救不了标签**——尺寸是 `TIERS` 写死的，
  只有分数是量出来的。
- **[G4] 档位选择性**：相邻两档 score 的 p50 严格递增 ∧ AUC ≥ 0.75。实测 39 → 51 → 81，
  AUC **0.796**（并列对 1.7%，480 对，距 0.5 有 3.3σ）与 **0.835**（0.7%，576 对，4.0σ）⇒ PASS。

所以「初学 / 熟练 / 高段」这三个标签只站得住一句话：**整盘的推理量随档位单调上升，且秩上可分**。
它不支撑"高段的每一盘都比熟练难"，也不支撑"每格更烧脑"（归一化那两条见上），也不支撑任何等待时间
的承诺。聚合命中率这一列另外带了每档"最大单盘独占多少"的披露（`balance` 输出第 [4] 段），本仓有过
一次聚合数被单个退化样本撑起来的事故，所以只看聚合数的报告一律欠这一列。

## 技术形态

- 浏览器原生 ESM，**零运行时依赖**；一块 `<canvas id="board">`（`index.html:45`）；CSS 一份
  `css/game.css`，全部相对路径——`pages-prefix` 腿就是专门量这个的（写死 `/css/game.css` 在线上会
  像它该那样 404，本地替它兜底等于门禁在给被测对象打补丁）。
- 本地起服务 `node server.cjs 5277`；桌面壳 `npm run electron`。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高——文件图标读文件头，
  内联成 base64 的图标先解码再读同一段。后一条不是可选项：图标可能住在清单里而不是盘上的 `.png`
  （有的仓另有一条"零二进制文件"的承诺，那条只约束"有没有 .png 这个文件"）；如果 P 段只筛文件名，
  声明写 512 而真图 192 就一路放行。
- **钉住两个数**：R 段实际检查的路径条数（`30`）与这一次跑的断言条数（`48`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字，也不写别仓文档闸的编号：有的仓的文档闸会拿"文档里出现过的同名标识号"回数它
  自己的条数，还有的会把文档里点到的每个组编号逐个核对"这一轮真的发过"——两道闸共用一个名字，
  或者在本仓的文档里出现一个本仓没有的组编号，打红的都是不相干的那一边。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`30`、断言仍然 `48`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug /
X13 内联位图谎报尺寸——只在有靶子时下：X11/X12 要页面上那句 og:image，X13 要清单里真有一段 base64
图标，没有就打印 SKIP；反过来 X1 没有位图目录可砍时改砍 css，P 段一位都不核时台架直接报靶子不够），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；本仓的整闸在 `tools/verify.sh` 的 `=== deploy-set ===` 那一段也各跑一次。它们红的时候并进本仓那条出口的退出码——这一条是这么证的：
把 ci.yml 里那行 `run: node tools/deploy-set.mjs` 砍掉，本仓整闸必须点名红且退出码非 0。
所以「本地全绿、线上 404 自己的 manifest / sw.js / 图标」这一类坏法在本地就会红。
